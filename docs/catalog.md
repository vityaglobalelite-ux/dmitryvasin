## Жёсткие решения (не пересматривать без человека)

1. **Из БД только динамика**, не весь сайт. В базе: продукты (уроки, курсы, лайфхаки, доп. материалы), цены, обложки и описания продуктов, длительность, уровень, навыки, состав курса, скидки, корзина, заказы, доступы, профиль, история покупок, уведомления. **Не из БД:** вёрстка, навигация, копирайт/маркетинг с макета, иконки, UI-хром, статические иллюстрации героя. Моки и JSON-дампы запрещены именно для динамики — не подставлять фейковый каталог «на время». Не использовать [src/lib/site-data.ts](../src/lib/site-data.ts) как каталог (старый Tilda).

**Загрузка динамики — скелетон**, не спиннер по центру и не пустой экран. Каркас совпадает с живой сеткой (обложка, строки текста, цена), мягкий шиммер в палитре макета, без скачка layout, когда приходят данные. То же для списков в кабинете, корзине, истории. Пустое и error — полноценные состояния (иллюстрация/типографика с макета, понятный CTA), не «нет данных».

**Уровень продукта:** максимально красиво, удобно, приятно глазу. Макет Figma — обязательный пол, не потолок: микровзаимодействия, hover/press, иерархия, ритм отступов, читаемость, без дёрганья и визуального шума. Не «лишь бы работало».
2. **Админки нет.** Уроки и карточки загружаются разработкой сразу в БД (миграции, скрипты). Не строить CMS «на всякий случай».
3. **Видео: Kinescope + DRM.** Хостинг и плеер — [kinescope.com](https://kinescope.com). Защита от скачивания / записи (DRM Widevine / FairPlay, приватные ролики, signed playback, запрет download в плеере, ограничение по домену). Не класть mp4 в `public/`, не отдавать прямую ссылку на файл в клиент. Токен воспроизведения — только после проверки, что у пользователя есть действующий доступ. В каталоге два языка видео (ru / en) — отдельные Kinescope id, не один ролик на оба.
4. Текущая схема `database-schema/` — боты клуба (`bot_users`, `subscriptions`, …). **Таблиц каталога ещё нет.** Их нужно спроектировать по сущностям ниже, а не подставлять фейковые строки в код.

## Пользовательский путь

Зашёл на сайт → увидел продукты → выбрал урок → описание → корзина → оплата → доступ → просмотр в личном кабинете.

## Экраны по ТЗ

### Главная

Первый экран: презентация (маркетинг) — изображение или видео, заголовок, короткий продающий текст, лозунг, доп. текст, кнопка в каталог или к продукту.

Каркас и маркетинговые тексты/картинки — из макета в коде. Карточки реальных продуктов в блоках — из БД (те же сущности, что в каталоге).

- Информационный: преподаватель (имя, фото, кратко, регалии, опыт, методика, преимущества) — статика с Figma, пока ТЗ не скажет иначе; переход в каталог.
- Продуктовый: карточки категорий — лайфхаки, уроки, курсы; записанные индивидуальные и доп. материалы — **требует уточнения** (Дмитрий упоминал без деталей). Переход в каталог. Если в блоке реальные товары — id/цены/обложки из БД.
- Маркетинговые: материалы с CTA открыть урок / курс / купить всё. Переход в каталог. Привязка CTA к живому продукту — через id из БД, не через захардкоженный «пример урока».

### Каталог

Все продаваемые продукты. Фильтры: лайфхаки, уроки, курсы, доп. материалы.

Пока список грузится — скелетон сетки тех же карточек (обложка + строки + цена). После ответа БД скелетон сменяется контентом без прыжка сетки.

Карточка: обложка, название, тип, короткое описание, стоимость.

| Тип | Дополнительно на карточке |
| --- | --- |
| Курс | число уроков, суммарная длительность, краткая программа |
| Урок | длительность, уровень / аудитория, основной навык |
| Лайфхак | краткое описание, длительность, основной результат |

Клик → страница продукта. Можно добавить в корзину.

### Страница продукта

Название, обложка, тип, стоимость, описание, длительность, уровень, навыки / темы, число видео, состав курса (если курс), срок доступа, кнопка покупки.

Не куплен → «Купить»: в корзину (см. Корзина). Второй путь покупки в ТЗ оборван — уточнять при реализации, не выдумывать checkout в обход корзины.

### Корзина

Список: название, изображение, стоимость, количество, итог, скидка, сумма к оплате. Удаление, назад в каталог, продолжить покупки, переход к оплате (банковская карта).

**Оптовая скидка:** при добавлении первого товара — модалка: чем больше товаров, тем больше скидка.

### Оплата

Из корзины. Не авторизован → регистрация / вход. Перед оплатой: состав, цены, скидка, итог, способ оплаты. Успех → продукт в кабинете.

### Регистрация / вход

Регистрация: email, пароль, подтверждение. Вход: email + пароль. Восстановление пароля. После входа — кабинет.

### Личный кабинет

Единая система с сайтом, не отдельный «портал». Разделы: мои уроки, история покупок, чат поддержки, уведомления. Выход.

**Мои уроки** (купленное): обложка, название, тип, дата покупки, срок доступа, таймер оставшегося времени, статус. Переход в продукт.

**История покупок:** название, тип, дата, стоимость, срок, оставшееся время, статус.

**Чат поддержки:** с сайта в Telegram-бота. Текст, изображение, файл.

**Уведомления:** новый ответ поддержки или смена статуса — внутри сайта, можно открыть.

### Заглушка по истечении доступа

Страница с предложением перейти в приложение и получить бонус: QR, ссылки на сторы.

### Общее

- Мультиязычность: ru / en.
- Видео дублируются на оба языка (два Kinescope id).
- Платёжные сервисы — интеграция, не заглушка «оплачено».
- Без админки.

## Сущности БД (ещё не созданы)

Проектировать таблицы/поля под это, не под мок:

- Пользователь: email, пароль (hash), сессия.
- Продукт: тип (`lifehack` \| `lesson` \| `course` \| `extra` — extra уточнить), цена, срок доступа, обложка, длительность, уровень, навыки, число видео, состав курса.
- Локализация продукта: ru / en (название, описания, программа, обложка при необходимости).
- Видео продукта: `locale`, `kinescope_video_id` (не URL файла).
- Корзина, позиции, применённая скидка.
- Заказ, платёж, статус.
- Выданный доступ: продукт, пользователь, куплен, истекает, статус.
- Сообщения поддержки → Telegram; уведомления на сайте.

Текущий Supabase (`api.betango.dance`) обслуживает ботов клуба. Каталог либо расширяет эту БД новыми таблицами, либо отдельная база — решение при проектировании схемы, не в UI.

## Видео / Kinescope

- Кабинет и страница купленного урока встраивают **официальный Kinescope Player** (iframe / SDK), не `<video src=mp4>`.
- Ролики приватные, DRM включён в кабинете Kinescope.
- Playback token / signed embed выдаёт бэкенд после проверки доступа и локали.
- На публичной карточке продукта — только обложка и метаданные, не рабочий плеер полного урока.
- Промо-ролик на главной, если будет, тоже Kinescope; не тащить хостинг с лендинга клуба.

## Открытые вопросы ТЗ (не закрывать заглушками)

- Записанные индивидуальные уроки и доп. материалы — состав и выдача.
- Второй путь кнопки «Купить» кроме корзины.
- Правила оптовой скидки (пороги %).
- Конкретный платёжный провайдер.
- Стор/QR на заглушке истекшего доступа.
- Как «Исследование» и «Уроки-подсмотры» из Figma ложатся на типы продуктов.
- Связь аккаунта каталога с Telegram / ботом клуба.

## Как агенту делать экран

1. Прочитать этот файл и правило `.cursor/rules/web-catalog.mdc`.
2. Figma MCP: skill `figma-design-to-code` → `get_design_context` нужной ноды + screenshot.
3. Динамика — типы и запросы к БД/API, без массивов «пример продукта». Статику экрана верстать по Figma в коде.
4. Пока грузится каталог и любые списки из БД — скелетон в форме карточек. Пустое/error — такие же аккуратные, как основной UI.
5. Видео — Kinescope DRM, не другой хостинг.
6. Доводить до ощущения готового продукта: удобство, ритм, глаз не цепляется за костыли.
